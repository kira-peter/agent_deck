# 确认对话框改进说明

> 历史记录：本文描述的是从"按键提示"到"选项列表"的中间方案（含 Y/N 快捷键），最终设计见 [confirmation-design.md](confirmation-design.md)。当前代码已移除 Y/N 快捷键。

## 改进内容

将确认对话框从"按键提示"模式改为"选项列表"模式，提供更直观的交互体验。

## 对比

### 之前的设计（按键提示）
```
┌─────────────────────────────────────────┐
│ 在此目录中打开 Claude Code?             │
│                                         │
│ D:\jarvis\claude-manager                │
│                                         │
│ Y: 是，打开   N: 否，重新选择   ESC: 取消│
└─────────────────────────────────────────┘
```
- 用户需要记住按键
- 没有明确的"当前选择"
- 需要一次性按对键

### 现在的设计（选项列表）
```
┌─────────────────────────────────────────┐
│ 在此目录中打开 Claude Code?             │
│                                         │
│ D:\jarvis\claude-manager                │
│                                         │
│ > Y: 是，打开 (Y)         ◄ 选中        │
│   N: 否，重新选择 (N)                   │
│   ESC: 取消                             │
│                                         │
│ ↑↓: 移动  Enter: 确认  Y/N: 快捷键  ESC: 取消│
└─────────────────────────────────────────┘
```
- 清晰的选项列表
- 高亮显示当前选择（绿底黑字）
- 可以用上下键浏览后再确认
- 仍然支持快捷键（Y/N/ESC）

## 优势

### 1. **更直观**
- 用户一眼就能看到所有可用选项
- 高亮的选中项明确显示当前将要执行的操作
- 箭头前缀 `>` 清晰标识选中状态

### 2. **更安全**
- 用户可以先用方向键"预览"每个选项
- 看到高亮的选项后再按 Enter 确认
- 减少误操作（如本想按 N，不小心按成 Y）

### 3. **更一致**
- 与整个应用的其他列表界面保持一致
- 与目录选择器的操作方式一致（上下键选择 + Enter 确认）
- 符合用户已经建立的操作习惯

### 4. **更灵活**
- 支持两种操作方式：
  - **方向键 + Enter**：适合谨慎用户，可以先看再确认
  - **快捷键（Y/N/ESC）**：适合熟练用户，直接按键执行
- 支持 Vim 风格键位（j/k）

### 5. **更易发现**
- 新用户即使不知道快捷键，也能通过上下键完成操作
- 括号中的快捷键提示帮助用户学习（如 `(Y)`）
- 底部的操作提示完整说明了所有可用方式

## 技术实现

### 数据结构变化
- 添加 `confirmSelectedIdx` 字段跟踪选中的选项索引
- 0 = 是，1 = 否，2 = 取消

### 交互逻辑
1. **初始状态**：默认选中第一个选项（"是，打开"）
2. **上下键**：在三个选项之间移动，实时更新高亮
3. **Enter 键**：执行当前选中的选项
4. **快捷键**：直接执行对应操作（向后兼容）
5. **ESC 键**：快捷取消（等同于选中"取消"并按 Enter）

### 视觉效果
- 选中项：`> 选项文字 (快捷键)` - 绿底黑字
- 未选中：`  选项文字 (快捷键)` - 白字
- 快捷键提示：灰色括号，选中时背景同步变绿

## 用户体验提升

### 场景 1：新用户
- **之前**：看到一排按键提示，不确定应该按哪个，可能误按
- **现在**：看到选项列表，可以用熟悉的上下键浏览，看到"是"高亮时按 Enter

### 场景 2：谨慎用户
- **之前**：想确认一下要按什么键，需要重新读一遍提示
- **现在**：用上下键慢慢看每个选项，确定选中"是"后再按 Enter

### 场景 3：熟练用户
- **之前**：直接按 Y 键
- **现在**：仍然可以直接按 Y 键（向后兼容）

### 场景 4：改变主意
- **之前**：按了 Y 后想取消，已经来不及了
- **现在**：看到"是"高亮但还没按 Enter，可以按下键改选"否"

## 实现细节

### 渲染逻辑（render.go）
```go
// 三个选项，垂直排列
options := []struct {
    label string
    key   string
}{
    {i18n.DirPickerConfirmYes.Get(), "Y"},   // 0
    {i18n.DirPickerConfirmNo.Get(), "N"},    // 1
    {"ESC: " + i18n.ConfirmNo.Get()[3:], "ESC"}, // 2
}

// 根据 confirmSelectedIdx 决定哪个高亮
if i == v.confirmSelectedIdx {
    style = style.Background(tcell.ColorLightGreen).Foreground(tcell.ColorBlack)
    prefix = "> "
}
```

### 事件处理（dirpicker.go）
```go
case tcell.KeyUp:
    if v.confirmSelectedIdx > 0 {
        v.confirmSelectedIdx--
        v.renderConfirmation()
    }
    
case tcell.KeyDown:
    if v.confirmSelectedIdx < 2 {
        v.confirmSelectedIdx++
        v.renderConfirmation()
    }
    
case tcell.KeyEnter:
    switch v.confirmSelectedIdx {
    case 0: // 是
        v.confirmed = true
        return fmt.Errorf("confirmed")
    case 1: // 否
        return nil
    case 2: // 取消
        v.cancelled = true
        return fmt.Errorf("back")
    }
```

## 测试建议

1. **基本导航**：测试上下键能否正常移动选中项
2. **Enter 确认**：测试在每个选项上按 Enter 是否执行正确操作
3. **快捷键**：测试 Y/N/ESC 快捷键是否仍然有效
4. **Vim 键位**：测试 j/k 是否能移动选中项
5. **视觉反馈**：确认高亮、前缀箭头、颜色变化都正确显示
6. **边界情况**：在第一项按上键、在最后一项按下键不应越界

## 总结

这个改进保持了向后兼容（快捷键仍然有效），同时为所有用户提供了更友好的交互方式。特别是对于不熟悉快捷键的新用户，选项列表模式大大降低了学习成本和误操作风险。
