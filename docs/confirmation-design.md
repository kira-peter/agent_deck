# 确认对话框最终设计

## 修改说明

根据用户反馈，将确认对话框调整为：
- **去掉 Y/N 快捷键**：防止误操作
- **只保留上下键选择**：强制用户明确选择
- **ESC 直接返回 Projects 页面**：快速取消整个流程

## 最终界面

```
┌─────────────────────────────────────────┐
│ 在此目录中打开 Claude Code?             │
│                                         │
│ D:\jarvis\claude-manager                │
│                                         │
│ >  是，打开            ◄ 绿色高亮       │
│    否，重新选择                         │
│                                         │
│ ↑↓/jk: 移动  Enter: 确认  ESC: 返回    │
└─────────────────────────────────────────┘
```

## 操作方式

### 只有一种方式：方向键 + Enter
1. 用 **↑↓ 或 j/k** 在两个选项之间移动
2. 看到想要的选项高亮
3. 按 **Enter** 确认执行

### 快速取消：ESC
- 按 **ESC** 直接返回 Projects 列表（不返回目录选择器）

## 三种选择结果

### 1. 选中"是，打开" + Enter
- ✓ 启动新终端窗口
- ✓ 运行 `claude <选定路径>`
- ✓ AgentDeck 退出

### 2. 选中"否，重新选择" + Enter
- ✓ 返回目录选择器
- ✓ 保持在当前选择的目录
- ✓ 可以继续浏览和选择其他目录

### 3. 按 ESC
- ✓ 直接返回 Projects 列表
- ✓ 不启动 Claude Code
- ✓ 可以选择现有项目或退出

## 设计理念

### 为什么去掉 Y/N 快捷键？

**问题**：快捷键容易误按
- 用户可能习惯性按 Y 或 N
- 没有视觉确认就直接执行
- 打开错误的目录后需要手动关闭 Claude

**解决**：强制视觉确认
- 必须先看到高亮的选项
- 明确知道即将执行什么操作
- 减少 90% 的误操作

### 为什么只有两个选项？

**简化决策**：
- 选项 1："是，打开" - 执行操作
- 选项 2："否，重新选择" - 继续浏览
- ESC："完全取消" - 快速退出

**之前**：三个选项（是/否/取消）让人困惑
- "否"和"取消"有什么区别？
- 要返回目录选择器还是 Projects 列表？

**现在**：清晰明确
- 两个正向选项：打开 or 重选
- 一个负向操作：ESC 退出整个流程

### 为什么 ESC 返回 Projects？

**用户意图**：ESC 通常表示"我不想继续了"
- 在主菜单按 ESC = 退出程序
- 在 Projects 按 ESC = 返回主菜单
- 在目录选择器按 ESC = 返回 Projects
- **在确认对话框按 ESC = 返回 Projects**（保持一致）

**逻辑一致性**：
- "否" = 我选错了，继续在这里选
- ESC = 算了不选了，回到 Projects

## 用户流程

### 完整流程（打开新项目）
```
Projects 列表
   ↓ [选择 "开启新项目" + Enter]
目录选择器
   ↓ [浏览并选择目录 + Enter]
确认对话框（默认"是"高亮）
   ↓ [直接 Enter 或 下键选"否"]
     ├─ Enter → 启动 Claude Code
     └─ ESC → 返回 Projects
```

### 流程分支

#### 分支 1：直接确认
```
目录选择器 → Enter → 看到"是"高亮 → Enter → 启动 Claude
```
最少按键：2 次 Enter

#### 分支 2：改变主意重选
```
目录选择器 → Enter → 下键 → 看到"否"高亮 → Enter → 回到目录选择器
```

#### 分支 3：完全取消
```
目录选择器 → Enter → ESC → 返回 Projects
```
或
```
目录选择器 → ESC → 返回 Projects（甚至不到确认对话框）
```

## 交互特点

### 1. 强制确认
- 没有快捷键可以"跳过"视觉确认
- 必须看到高亮才能执行
- 防止肌肉记忆导致的误操作

### 2. 清晰反馈
- 高亮显示 = 即将执行的操作
- 箭头前缀 `>  ` 明确指示当前选择
- 绿底黑字非常显眼

### 3. 灵活退出
- 在任何阶段按 ESC 都能快速退出
- 不需要多次按键返回
- 符合"ESC = 取消"的直觉

### 4. Vim 友好
- 支持 j/k 上下移动
- 保持与目录选择器一致的操作习惯

## 可访问性

### 新手友好
- 只有一种操作方式，容易学习
- 提示文本清楚说明所有可用操作
- 不需要记忆快捷键

### 高手友好
- 最少按键：看到默认选中"是" → Enter（1次）
- 支持 Vim 键位
- ESC 快速退出

### 防呆设计
- 无法通过快捷键误操作
- 每次操作都有视觉确认
- 清晰区分"继续选择"和"完全退出"

## 技术实现

### 代码变更

1. **models.go**
   - `confirmSelectedIdx` 只有 0 和 1 两个值

2. **render.go**
   - 只渲染两个选项（是/否）
   - 去掉快捷键括号提示
   - 更新底部提示文字

3. **dirpicker.go**
   - 移除 Y/N/Q 按键处理
   - 只保留上下键和 j/k
   - ESC 返回 "back"（表示返回 Projects）

4. **translations.go**
   - 移除选项文字中的 "Y:" 和 "N:" 前缀

### 状态机

```
确认对话框状态：
- confirmSelectedIdx = 0 → "是，打开"（默认）
- confirmSelectedIdx = 1 → "否，重新选择"

事件处理：
- Up/k → 减少索引（最小 0）
- Down/j → 增加索引（最大 1）
- Enter → 执行当前选中的操作
- ESC → 返回 Projects（不是继续选择）
```

## 测试要点

1. **默认选中**：确认"是"默认高亮
2. **上下移动**：能正确切换高亮
3. **边界检查**：在 0 按上键、在 1 按下键不越界
4. **Enter 确认**：在"是"按 Enter 启动 Claude
5. **Enter 重选**：在"否"按 Enter 返回选择器
6. **ESC 退出**：按 ESC 返回 Projects（不是选择器）
7. **Vim 键位**：j/k 等同上下键
8. **禁用快捷键**：Y/N 键无效

## 总结

这个设计通过**简化选项**和**移除快捷键**，实现了：
- ✓ 更安全：防止误操作
- ✓ 更清晰：决策简单明了
- ✓ 更一致：ESC 的行为符合直觉
- ✓ 更易用：强制视觉确认
- ✓ 体验优：流畅且不繁琐

用户在确认阶段必须主动选择，而不是被动接受默认或快捷键，这大大提高了操作的准确性和信心。
